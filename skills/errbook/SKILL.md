# errbook · 构建错误错题本

errbook 是纯本地的错误记忆库：错误按签名归档，修法跟着错误走。
同一个坑第二次出现时，`errbook check` 的第一句话就是"这错你修过，上次怎么好的"。
**修复知识要变成结构化资产，不要烂在会话里。**

## 核心循环（每次构建/运行失败都要走）

1. **失败先查本**：拿到错误输出后立即运行
   `errbook check --file <log>`（或把错误文本管道给 `errbook check`）。
   也建议从一开始就用包装器跑构建：`errbook run -- <原命令>`——输出与
   退出码原样透传，错误自动入库，命中历史会直接追加提醒。
2. **命中 → 先读历史修法再动手**：提醒块里有"上次怎么好的"。先判断
   是否同款（原文摘录并排展示，由你确认），是同款就优先复用修法；
   不是同款，正常修。
3. **未命中 → 正常修**：check 没有输出就是没见过，正常排查。
   注意 check 退出码恒为 0，它只是信息附加器，不能当门禁。
4. **修好必须 solve**（灵魂步骤，漏了等于白修）：
   `errbook solve <sig-id> "<一句话怎么好的>"`
   sig-id 在 check/run/add 的输出里，可只写前缀。同一错误不同根因，
   就再 solve 一次，会追加成列表。

## 命令速查

| 命令 | 用途 |
|---|---|
| `errbook run -- <cmd>` | 包装构建命令：透传 + 捕获入库 + 命中提醒（推荐默认用法） |
| `errbook check --file <log>` | 拿一段错误文本查历史（stdin 也行；退出码恒 0） |
| `errbook solve <sig-id> "<怎么好的>"` | 记录修法（自动附记 git HEAD，若在仓库内） |
| `errbook add --file <log>` / 管道 | 手动粘贴错误入库（错误来自远程 CI 日志等无法包装的场景） |
| `errbook search <关键词>` | FTS 全文搜错误与修法（中文子串可以） |
| `errbook show <sig-id>` | 看完整档案：归一化签名、修法列表、出现记录 |
| `errbook top [--all]` | 高频错误排行（默认当前项目） |
| `errbook forget <sig-id>` | 删掉某个签名（连同修法与出现记录） |

## 红线与注意

- 纯本地零网络：摘录永不外传；入库前已自动截断 + 脱敏（token/密钥打码），
  但也不要主动把大段无关日志喂给它——贴错误本身。
- `check` 默认不出 fuzzy 命中（归一化没把握的），`--fuzzy` 才看；
  fuzzy 命中要人工判断是否同款，不要盲信。
- 多项目隔离：查询默认当前项目（git remote 名或目录名），`--all` 跨项目。
- 把 `errbook run --` 当默认包装习惯用，agent 会话输出易截断/转义，
  包装器是最可靠的采集入口；add 只做兜底。
